MLP & GNN on V̂(s): Data, Architecture, Training, Evaluation

experiments_after_understanding · mlp, gnn, two_gene, myopic

How V̂(s) is built, trained, and scored

Two models — an MLP and a GNN — learn to approximate the exact-DP optimal value function V*(s) for a sequential genetic-testing problem over a pedigree. This is a full method reference: the raw features, how each model turns them into an embedding, how training works, how the resulting policy is evaluated, and the final head-to-head numbers against two non-learned baselines — a training-free myopic heuristic, and an ADP linear-value baseline. 2-gene and 3-gene are now trained under matched conditions (see the Training section) after a methodology fix applied this session.

Dataset & split

Train on two families, test on a third, unseen one

Both models are trained on Trio and Nuclear pedigrees and evaluated, without any further fitting, on ThreeGeneration — a family topology neither model has seen. Every family is instantiated across 6 allele-frequency regimes × 2 cost presets = 12 configs. Ground-truth labels (V*(s) and the exact belief propagation used at evaluation time) come from exact dynamic programming, cached per config as a pickle.

What "message passing" does, concretely

Two rounds over the ThreeGeneration pedigree

Edges only run parent → child (build_edge_index()). Messages flow one way, so after two rounds a person's embedding reflects everyone up to two generations above them — never below.

parent → child edge (fires every round)
traveling message

Round 1: Father absorbs Grandfather + Grandmother; Child absorbs Father + Mother (Father's round-0 features only). Round 2: the same 4 edges fire again, but Father's embedding now already contains the grandparents — so Child's round-2 update inherits them second-hand. Grandfather, Grandmother, and Mother have no incoming edges: their embeddings only ever reflect their own features.

Function reference

The three functions that build embeddings

Source: experiments_after_understanding/mlp/run.py and experiments_after_understanding/gnn/run.py (3-gene). The 2-gene versions in two_gene/run.py are line-for-line identical logic, just NODE_FEAT=10 / COST_DIM=8.

MLP.forward(node_feats, cost_vec) mlp/run.py

The whole model in one call: pool people into a single vector, glue on the cost vector, run a 2-layer MLP. No parameter here is aware of who a person is related to.

input
node_feats (B, N_people, 13) · cost_vec (B, 11)
output
V̂ — (B,) scalar per state
  1. 1pooled = node_feats.mean(dim=1) — average every person's 13-dim row into one 13-dim vector. This is the embedding: unlearned, order- and structure-blind, just an arithmetic mean.
  2. 2x = cat([pooled, cost_vec]) — append the 11-dim cost vector (test costs, allele-effect coefficients), giving a 24-dim input.
  3. 3self.net(x) — Linear(24→32) → ReLU → Linear(32→1), squeezed to a scalar.
def forward(self, node_feats, cost_vec):
    pooled = node_feats.mean(dim=1)                 # (B, 13) — mean pool: size-invariant
    x      = torch.cat([pooled, cost_vec], dim=-1)  # (B, 24)
    return self.net(x).squeeze(-1)             # (B,)
GNN._message_pass(h, src, dst, msg_fn, upd_fn) gnn/run.py

This is the actual embedding-builder. Called once per round (twice total). Takes the current per-person embeddings and returns updated ones that have absorbed one hop of relatives.

input
h (B, N, F) · src, dst (E,) edge index · msg_fn, upd_fn (this round's 2 small nets)
output
h_new — (B, N, 32) updated per-person embeddings
  1. 1msg_in = cat([h[src], h[dst]]) — for every parent→child edge, pair the parent's embedding with the child's current embedding → (B, E, 2F).
  2. 2msgs = msg_fn(msg_in) — a learned Linear→ReLU turns each pair into a 32-dim message → (B, E, 32).
  3. 3agg = scatter_add(msgs, dst) — sum every message landing at the same child; a person with two parents receives and sums two messages → (B, N, 32).
  4. 4h_new = upd_fn(cat([h, agg])) — a second learned layer combines each person's own previous embedding with what arrived, producing the updated embedding. People with no incoming edges (roots) get agg=0 and are updated from their own features only.
def _message_pass(self, h, src, dst, msg_fn, upd_fn):
    msg_in = torch.cat([h[:, src, :], h[:, dst, :]], dim=-1)  # (B, E, 2F)
    msgs   = msg_fn(msg_in)                                     # (B, E, H)

    agg = torch.zeros(B, N, H, device=h.device)
    idx = dst.unsqueeze(0).unsqueeze(-1).expand(B, -1, H)
    agg.scatter_add_(1, idx, msgs)                              # sum at each dst node

    return upd_fn(torch.cat([h, agg], dim=-1))                 # (B, N, H)
GNN.forward(node_feats, edge_index, cost_vec) gnn/run.py

Orchestrates _message_pass() for n_rounds=2, then pools — mirrors MLP.forward exactly from the pooling step onward, so any performance difference between the two models comes entirely from what happens before this point.

input
node_feats (B, N_people, 13) · edge_index (2, E) · cost_vec (B, 11)
output
V̂ — (B,) scalar per state
def forward(self, node_feats, edge_index, cost_vec):
    h   = node_feats
    src, dst = edge_index[0], edge_index[1]

    for msg_fn, upd_fn in zip(self.msg_layers, self.upd_layers):   # 2 rounds
        h = self._message_pass(h, src, dst, msg_fn, upd_fn)   # (B, N, 32)

    pooled = h.mean(dim=1)                            # (B, 32) — mean pool: size-invariant
    x      = torch.cat([pooled, cost_vec], dim=-1)  # (B, 43)
    return self.head(x).squeeze(-1)              # (B,)

Training mechanism

Supervised regression to exact-DP labels

MLP and GNN are trained identically: minimize MSE between V̂(s) and the exact-DP label V*(s) for every state in the training pool, with Adam. Myopic is not trained at all — it is a closed-form one-step-lookahead policy computed directly from the cached exact belief states. ADP is also not trained on Trio/Nuclear — see the callout below the table.

2-gene originally had no validation split at all — two_gene/run.py's train_model() was a separately-written function that never carried over the val_frac split logic from mlp/run.py/gnn/run.py's train(); it trained on 100% of the 32,352 states with no held-out signal at all. This was fixed (patched into train_model() to match exactly) and both 2-gene models were retrained fresh; the numbers throughout this document now reflect that fix. The pre-fix run is preserved at two_gene/results/pre_valsplit_backup/ for audit purposes — see the instability callout in Results below for why that before/after comparison matters.
ADP is not the same kind of baseline as MLP/GNN/Myopic. adp/run.py / two_gene/adp_run.py fit theta by solving a Bellman-consistency linear program (solve_adp()) whose constraints come directly from each ThreeGeneration test config's own states, beliefs, and transition probabilities — never from Trio/Nuclear, and never from V*(s) labels, but with full access to the exact structure of the very family it's then scored on. That is fundamentally different from MLP/GNN's zero-shot Trio+Nuclear→ThreeGeneration transfer, so ADP's numbers are reported alongside the others for completeness but are not a fair apples-to-apples comparison to MLP/GNN/Myopic.

What one epoch actually does (mlp/run.py, gnn/run.py identical structure)

for epoch in range(1, epochs + 1):
    model.train()
    for g in train_groups:                       # one group per training config (24 total)
        perm = torch.randperm(M, device=device)     # reshuffle this config's states every epoch
        for start in range(0, M, batch_size):    # batch_size = 512
            pred = model(g["nf"][sl], g["gf"][sl])   # (+ g["ei"] for GNN)
            loss = mse(pred, g["y"][sl])
            loss.backward(); optimizer.step()

    # mlp/run.py, gnn/run.py only: held-out val_groups scored every epoch, logged every 50th
    model.eval()
    with torch.no_grad():
        for g in val_groups:
            val_loss += mse(model(...), g["y"][...]).item()

Minibatches are drawn within each of the 24 training configs separately (never mixed across configs in one batch), reshuffled every epoch. Final weights are whatever the model looks like after the full epoch budget — no checkpoint selection on best-val, since nothing in the main training loop compares epochs against each other.

gnn_proper_val/ variant, not used below: a separate script (gnn_proper_val/run.py) holds one whole regime (MixedB) out of training as a proper generalization-val set and adds early stopping (patience=50). It reports avg ratio2 = 0.0386 on the same 12 ThreeGeneration test configs, but under a different 20-config training split, so it is not apples-to-apples with the MLP/Myopic numbers below and is intentionally excluded from the results tables.

Evaluation mechanism

Greedy rollout, scored by exact expectation

All three policies (Myopic, MLP, GNN) are scored the same way, on the same 12 ThreeGeneration configs, by rollout() in exputils/eval.py (myopic uses its own near-identical myopic_policy_value() in myopic/run.py). The only thing that differs between policies is which score each uses to pick the next person to test.

Per-step decision rule

At every state s, for every untested person i, each policy scores the option of testing them next:

MLP / GNNQ̂(s, i) = r_test(i, s) + Σg P(g | s, i) · V̂(s ∪ {(i,g)})
MyopicQ_myopic(s, i) = r_test(i, s) + Σg P(g | s, i) · V_stop(s ∪ {(i,g)})
ADPQ_ADP(s, i) = r_test(i, s) + Σg P(g | s, i) · φ(s ∪ {(i,g)}) · θ

The difference is entirely in the bolded term. MLP/GNN plug in the trained model's estimate of the true optimal future value at the hypothetical next state — in principle a multi-step-lookahead estimate, if V̂ were accurate. Myopic plugs in the exact value of stopping immediately after that one test — a genuine one-step lookahead, computed exactly, with no learned approximation and no foresight beyond the next test. ADP plugs in a linear function of 16 hand-designed "ABCD" features (φ(s)), with the weight vector θ fit once per test config by solving a Bellman-consistency LP against that config's own exact states (never trained on Trio/Nuclear, never regressed on V* — see the training-mechanism caveat above). All four policies then apply the same rule: stop if max_i Q(s,i) ≤ v_stop(s), else test argmax_i Q(s,i), where v_stop(s) = Σk not tested r_reward(k) is the exact cost of stopping right now.

Scoring the induced policy: exact expectation, not sampling

Once a policy picks its action at every state, the achieved value L is not a Monte-Carlo average over sampled rollouts. It is computed by recursing through the actual exact-DP state graph, weighting every branch by its true transition probability:

def value_at(state):                        # memoized
    if no untested people: return 0.0
    best_i = argmax_i Q(state, i)               # policy-specific Q from above
    if Q(state, best_i) <= v_stop(state):
        return v_stop(state)                   # policy stops here
    return r_test(best_i, state) + sum(
        P(g | state, best_i) * value_at(state ∪ {(best_i, g)})
        for g in genotypes
    )                                            # exact expectation over test outcomes

L = value_at(root_state)

This means L is the true expected value of following that policy from the root — every possible test-result branch is included, weighted exactly, not one sampled path.

ratio2 — the metric in every results table

ratio2 = ( V* − L ) ÷ ( V* − V_stop(root) )

V* is the true optimum from exact DP (same for every policy on a given config — it doesn't depend on the model). V_stop(root) is the value of testing no one at all. So: ratio2 = 0 means the policy matches the exact optimum; ratio2 = 1 means it does exactly as poorly as never testing anyone; ratio2 > 1 means it is worse than doing nothing at all — which does happen in the tables below (MLP, LowLow_Base, both gene counts).

exputils/eval.py: rollout(), _q_hat(), _stop_val() — used by mlp/run.py, gnn/run.py, two_gene/run.py. myopic/run.py: myopic_policy_value(), compute_v_stop(), compute_r_test() — structurally the same value_at() recursion, different Q.

Reading the tables together

  • Myopic wins on average in every column, both settings (0.0421 / 0.0269) despite requiring no training data and no learned parameters at all — it remains the strongest, cheapest baseline on this task even after fixing 2-gene's methodology and adding ADP.
  • MLP is the worst-or-near-worst policy on average in both settings (2-gene: 0.2240; 3-gene: 0.1358, worst in that table) and produces the single largest same-family failure in the 3-gene table (LowLow_Base = 0.8807, worse than testing no one at all).
  • ADP is now the worst policy on average in 2-gene (0.2303) and second-worst in 3-gene (0.1053) — despite having privileged access to each test family's own exact structure (see the training-mechanism caveat). Its own LowLow_Base numbers are the worst single value in both tables (2-gene: 1.5655; 3-gene: 0.6830) — this regime is hard for every approximate method here, not a MLP-specific weakness.
  • GNN is the best of the three non-myopic methods in both settings post-fix (2-gene: 0.1744; 3-gene: 0.0447), but still doesn't beat myopic on average, and the 2-gene number is exactly the one shown above to be unstable across a single unseeded rerun — treat it as a rough indicator, not a settled result.
  • None of this rules out that the ranking is mostly a training-loop artifact: the val-loss table above shows 2-gene GNN's shipped checkpoint is 8.5× worse than its own best; a version of this pipeline with best-val checkpointing (not yet run) could plausibly change every number in both tables.

Seed stability · 3 seeds, same everything else

The single-run numbers above were not representative

None of the original scripts set a random seed anywhere (checked: no torch.manual_seed in mlp/, gnn/, two_gene/, myopic/, gnn_proper_val/, or adp/). To find out whether that mattered, three new, separate scripts — mlp/run_seeds.py, gnn/run_seeds.py, two_gene/run_seeds.py — were written as backward-compatible copies of the originals (the originals are untouched; these just add --seed, call torch.manual_seed(seed) before model init, and write to results/seed_runs/seed{N}/ instead of overwriting results/). Each was run for seeds 0, 1, 2 — architecture, data, split, epochs (500), batch size (512), optimizer, and loss all identical to the canonical runs, only the seed differs. All 9 jobs (SLURM 2107149/2107150/2107151) completed successfully.

MLP has a collapse failure mode GNN never shows

Counting how often the induced rollout policy tests nobody at all (ratio2 exactly 1.0000, i.e. it stops at the root state) across all 36 seed×config runs per setting:

SettingCollapsed to "test no one"
MLP (3-gene)4 / 36 (11%)
MLP (2-gene)9 / 36 (25%)
GNN (3-gene)0 / 36 (0%)
GNN (2-gene)0 / 36 (0%)

A quarter of the time, 2-gene MLP's trained V̂ makes every possible test look worse than doing nothing at the very first decision — even in regimes (e.g. LowHigh_Base, one of three seeds) where testing is clearly valuable, as shown by myopic and GNN both testing productively there in the same regime. GNN never does this, in either gene count, across all 36 runs. This is a reproducible architectural weakness specific to the mean-pool MLP, not a description of "MLP is somewhat worse on average" — it's a distinct, discrete failure mode with its own rate.

What changes once you stop trusting a single run

  • Myopic's advantage over both neural models is larger than the single-run tables suggested, not smaller. 3-gene GNN's true average (0.0737) is 65% worse than the single lucky run reported earlier (0.0447); 2-gene MLP's true average (0.3985) is roughly double either single run shown above (0.2240 / 0.2333).
  • GNN is consistently more stable than MLP (lower std in nearly every regime, in both gene counts) in addition to having a better mean — and never exhibits the collapse-to-root failure mode.
  • Some regimes are unstable for every method, not just the weak ones: LowLow_Base has enormous std even for GNN (2-gene: ±0.7552; 3-gene: ±0.1938) — this looks like a property of the regime itself (rare alleles, low signal), not something either architecture can fix by training harder.
  • Three seeds is still not enough to report tight confidence intervals — it's enough to prove the single-run numbers were unreliable, not enough to pin down the "true" mean precisely. Treat the values in this section as a much better estimate than anything above, but still not a final answer.
